# Liesma consolidated tileset and separate city copies

Created `gTileset_Liesma` in `data/tilesets/secondary/liesma` from only the
metatiles referenced by LiesmaCityNorth, LiesmaCitySouth, their borders, and the
6×5 double-tiered house on liesmatest. The primary General tileset is unchanged.

## Maps

- `LiesmaCityNorth2`: 65×40, same blocks/collisions/events as original North.
- `LiesmaCitySouth2`: 67×48, same blocks/collisions/events as original South.
- Both new maps are appended to map group **testingstage** (existing IDs stay
  stable). Their mutual North/South connections point to the new copies.
- The originals and route connections are unchanged. The new copies retain
  their outgoing links to the original surrounding routes, but those routes
  still lead into the original city. These are separate check-first copies,
  not a replacement of the existing game world.
- `liesmatest` now uses Liesma and previews the new pink-roof/cream house.
  The house is available in the tileset but was **not** placed over existing
  buildings in the two city copies.

## Space and colours

- 338 metatile slots including the blank slot; **174 blank slots remain**
  (`0x352–0x3FF`). The house's 21 slots occupy `0x33D–0x351`.
- 252 compiled graphic tiles; **252 usable slots remain** before the door
  animation's reserved `0x3F8–0x3FF` VRAM tiles.
- Flag slots `0x2DA–0x2DF` are reserved, never treated as static graphics.
- House uses palette **7** (pink roof and neutral-grey trim), **8** (cream
  facade, beige columns and original blue glass), and original primary palette
  **5** for its unchanged wooden door. Palettes **6 and 11** remain unused by
  visible static or animated graphics. Palette 11 is referenced only by blank
  transparent tiles; it is safe to repurpose together with those references.
- North's used palettes 9/10/12 are retained. City map renders are exactly
  RGB-identical before/after remapping. Collision/elevation bits, tile pixels,
  flips, behaviours, dimensions and original source assets are preserved.

## Animations

- Both original flag frame sequences are identical. All four are copied into
  Liesma's own animation folder; a dedicated `InitTilesetAnim_Liesma` callback
  reads those copies with the original eight-tick timing and VRAM positions.
- Liesma is registered in the project-local Porymap animation plugin too.
- Used secondary door registrations are remapped (Battle Dome and generic
  Frontier door); primary General doors continue using their unchanged table.
- The house has an independent `graphics/door_anims/liesma_wooden.png` copy.
  Palette array `{7,7,8,8,5,5,5,5}` matches the roof strip, facade lintel, and
  wooden door. Two unused facade indices retain the original wood colours in
  the upper portion of moving frames. The original door PNG is unchanged.
- PNG frames are opening frames; the engine draws the closed door from the
  metatiles, so the first PNG frame is intentionally not a closed-door image.

## Backup and verification

`before/` includes full original map folders and layouts for both city maps and
liesmatest, the original General/West/East/Lilycove assets, original wooden door,
and registration-source snapshots. **Do not restore entire registration files
over subsequent work.** The original city maps are still available unchanged.

`manifest.json` maps every old metatile to its new ID and records the source
layouts and allocations. Native before/after renders and `house_preview.png`
are generated by the read-only verification command:

```
python3 dev_artifacts/liesma/build.py --verify
node dev_artifacts/tileset_animation_audit/verify.mjs
```

`--prepare` is a one-shot guarded construction step, not a restore command;
`--refine-door` is the separate deterministic pixel-index refinement used in
this implementation. Do not rerun preparation on an existing tileset.

Verification and `make -j4` passed after the final colour adjustment. The ROM
built successfully; appearance/door behaviour has not been tested in an emulator.
